NeuroVault · interactive mockup

The NeuroVault front end, R7: the PRD's features on the Vault Notes design. Every view now opens as a tab, like Obsidian. The top bar holds the quick actions: quick timer, sticky note, brain dump, voice ramble, reading ruler, sensory comfort (Aa), wrap-up and Ctrl+K. Everything inside the frame is clickable, and the floating widgets can be dragged. The "Open panel" and "Floating widgets" switches (Data tab) jump straight to each new screen. The parts gallery below shows every control in each state. Lock the options you like with "🔓 Lock", then use "Save locked copy" in Decisions. Options marked • are new proposals. This file is standalone: it needs no server, internet or other files.

Notes · findings, what it keeps, parts used, checks

Findings in the pasted code

  1. The script doesn't run. After let currentEditorMode there is a stray fragment of a commits list (Node: SyntaxError: Unexpected token ':'). tasks, branches, commits and activeTaskFilter are never declared; selectNote and navigateHistory are called but never defined; addNewTask is defined twice and there are two stray }. So the notes list, editor, tasks, branches and graph all render empty. The mockup supplies working versions.
  2. Muted text fails contrast. --text-muted #8c8984 on #f6f5f2 is about 3.2:1 (AA needs 4.5:1). "Paper R0" keeps it; the other themes raise it.
  3. Colours outside the tokens: priority colours (#ef4444 / #f59e0b / #10b981), graph node and edge colours, and the branch diagram are hard-coded, so they ignore dark mode and any accent change. The mockup draws them from tokens.
  4. Selected state drawn six different ways through inline styles (rail, notes list, filters, branches, tabs, editor mode). Here they share one "current" style: accent tint.
  5. Monospace for labels: eyebrows, counts and the status bar use OpenDyslexicMono. The house rule keeps mono for copyable codes only (file paths, commit hashes).
  6. A debug button in the editor toolbar ("Test AST Bug"). In the mockup it is the State → "Parser bug" option instead.
  7. Delete note has no confirmation. The mockup asks first.
  8. Text down to 10.5px in several places; with a dyslexia font that is hard to read. The smallest size here is 11px, scaled by Text size.
  9. The font override uses * {… !important}, which blocks any font choice. Here the font is one token.

Findings in the NeuroVault timer (R5)

  1. A running session is lost if the app closes: pauses, check-ins and time are only written on Stop & log.
  2. Project colours are stored as fixed hex values (#34e0e0, #f5b45a…), so they ignore the theme. The mockup uses six colour slots defined per theme; storing the slot number instead would keep contrast in every theme.
  3. "Can't delete a project with sessions" is only enforced in the page. The backend's delete_project deletes it anyway (sessions fall back to no project).
  4. The pause reasons, check-in and settings controls are <div>s, so they can't be reached with Tab or used from the keyboard. The mockup uses buttons and switches with ARIA state.
  5. Energy and focus use sliders for a 1–5 choice: dragging for one of five values is slow and the value is easy to miss. "1–5 buttons" is offered as an option.
  6. The theme setting sits in the Timer's settings dialog although it changes the whole app. In the mockup the Timer settings hold only timer things.
  7. Inline styles on the heatmap, its legend and the mode toggle; colours like the ring gradient are hard-coded. Here everything comes from tokens.

Building R7 in the app

  1. Storage first: notes become .md files in the vault folder (the database becomes an index). Sticky notes, _inbox.md, .html files, PDF conversion, attachments/ and .neurovault/history/ all depend on it.
  2. Server: serve the frontend from a FastAPI loopback port (127.0.0.1) so WebView2 keeps microphone permission; WebSockets keep pinned widget windows in step with the main window.
  3. Pin to desktop: webview.create_window(..., frameless=True, on_top=True, easy_drag=True) per widget; close them all from window.events.closed. A tray icon keeps a running session alive.
  4. Local tools: sherpa-onnx (Whisper speech-to-text, Kokoro / Piper read-aloud), a bundled WordNet SQLite file, Docling or MarkItDown for PDF to Markdown, WeasyPrint for export. Bundled files load through resource_path().

Building R6 in the app (pywebview)

  1. Window bar: create the window with frameless=True, easy_drag=False; the bar's drag area carries the pywebview-drag-region class. The three buttons call the API, which runs window.minimize(), window.maximize() / window.restore() and window.destroy(). A frameless window loses Windows' resize edges, so keep resizable=True and check edge-resizing on Windows 11 before locking "Drawn by the app".
